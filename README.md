# LUMA Liver Unified Modelling & Analytics

LUMA is an offline, synthetic research prototype for exploring marker arithmetic and illustrative liver systems equations. **It is not a diagnostic, prognostic, medical-device, or treatment-planning tool.** Do not enter patient, identifying, or real genomic data. Low synthetic fit error measures recovery of generated equations only; it does not show biological or clinical accuracy.

## Competition submission overview

### Project title

**LUMA — Liver Unified Modelling & Analytics**

### Problem statement

MASLD involves interacting metabolic and tissue processes, while many software demonstrations show outputs without making assumptions or model calculations inspectable. LUMA provides a local, reproducible sandbox for examining simplified equations and synthetic inputs. It is a software and research prototype, not a validated representation of patient biology.

### Healthcare use case

The intended demonstration use is educational and exploratory: inspect how synthetic laboratory history and a synthetic wearable-like activity, sleep, and heart-rate stream flow through declared model assumptions, then compare resulting dimensionless states and a synthetic forecast benchmark. It is not intended for screening, diagnosis, prognosis, treatment selection, clinical workflow, or patient care. Do not enter real health or identifying information.

### Technical stack

- **Backend/API:** Python 3.13.16+, 3.14.8+, or 3.15; Python standard library HTTP server; loopback-only JSON API.
- **Frontend:** HTML, CSS, and native JavaScript ES modules.
- **3D visualization:** locally hosted Three.js modules and licensed GLB anatomy assets.
- **Training/evaluation:** deterministic synthetic data, ordinary least-squares (OLS) derivative surrogate, ridge comparator, synthetic holdout metrics, and a separate synthetic 30-day target benchmark.
- **Storage/deployment:** no database or persistence; local demonstration only.

### AI/ML model and framework details

The mechanistic demonstration evolves four dimensionless states (FFA, triglyceride proxy, ROS proxy, and ECM proxy) using a forward-Euler solver. Four OLS linear regressors approximate derivatives generated by the project's own illustrative equations. The checked-in model was trained on 8,000 generated equation samples; the 80/20 split is used for equation-recovery evaluation only. The two-stream demo has an additional OLS forecast for a synthetic dimensionless TG proxy at 30 days, trained on 400 generated records and evaluated on 100 separately generated held-out records against persistence. Its ground truth is an independent synthetic equation. None of these outputs is trained on or validated against patient data. See [the model card](docs/MODEL_CARD.md), [synthetic training notes](docs/SYNTHETIC_TRAINING.md), and [experiment report](reports/experiment_report.md).

## Run locally on Windows

Python 3.15.0 is the documented baseline for this release. The runtime guard also accepts final Python 3.13.16+ and 3.14.8+ releases. Check installed interpreters with `py -0p` and verify with `py -3.15 --version`.

From the extracted project folder in PowerShell:

```powershell
# Isolated environment and synthetic model artifact
py -3.15 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe src\train_synthetic.py

# Start the frontend and local API
.\.venv\Scripts\python.exe src\server.py
```

Open <http://127.0.0.1:8765/>. Click **Run model** beside the input heading to run the current values; this action stays visible while scrolling through inputs. Click **Load example** to populate and run the sample scenario. The same run action is also available at the bottom of the input form. Validation or API errors are brought into view. Keep the terminal open; press `Ctrl+C` to stop the server. It binds to loopback only and does not store inputs or results. Runtime settings are read from the process environment; see [`.env.example`](.env.example). There is no `.env` loader, so set variables in PowerShell, for example `$env:MASLD_PORT = "8766"`.

If the checked-in model file is missing or invalid, server startup trains a clearly labeled **memory-only synthetic fallback** (8,000 generated rows, fixed seed). It does not modify files. The health route identifies the fallback. Run the trainer command to regenerate the checked-in artifact and its experiment reports.


The default output is `../masld-digital-twin-release.zip`. The packager excludes caches, compiled Python, virtual environments, build output, secrets, and nested ZIPs. ## Project structure

```text
backend/masld_app/api/       HTTP handler, versioned routes, API errors
backend/masld_app/domain/    Input schema, marker arithmetic, scenarios, ODE/PDE
backend/masld_app/services/  Synthetic data, training, evaluation, artifacts, inference, two-stream demo
web/                         Accessible frontend, modular JS/CSS, local GLB/vendor assets
src/                         Stable CLI, server, and training entry points
tests/                       Unit, API, packaging, and Playwright browser coverage
docs/                        API, architecture, data, model card, security, test notes
model/                       Synthetic derivative-surrogate artifact
reports/                     Reproducible synthetic metrics and diagnostics
examples/                     Synthetic-only example input
```

UI code calls the same-origin `web/assets/js/api-client.js`; `backend/masld_app/api/` validates and routes requests; `services/` owns training/artifact/inference; `domain/` owns arithmetic and simulation. The server has no database, accounts, outbound integrations, or external runtime dependencies. Three.js modules are vendored locally.

## API

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/v1/health` | Model status, source, version, provenance, limitations |
| `POST` | `/api/v1/model` | Validated synthetic marker arithmetic and simulation |
| `GET` | `/api/v1/demo` | Fixed synthetic lab + sensor story, fused twin, and held-out forecast benchmark |
| `GET` | `/api/health` | Compatibility alias |
| `POST` | `/api/model` | Compatibility alias |

Example:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/v1/model `
  -ContentType 'application/json' -Body '{"age_years":45,"reduce_uptake":true}'
```

Responses contain model metadata, marker summaries, zone histories, baseline/scenario comparison, sensitivity summaries, and signed TG/ROS/ECM surrogate feature contributions. The Explainability Dashboard follows the selected metric, scenario, zone, comparison mode, and playback step; it reconciles integrated terms with state change and the non-negative clamp. Exact response shape and limitations are in [docs/API.md](docs/API.md) and [the model card](docs/MODEL_CARD.md). Errors have the form `{"error":{"code":"...","message":"..."}}`. The server checks JSON content type, UTF-8 JSON object shape, finite numeric ranges, request size, local Host/Origin, rate limit, worker count, and socket timeout. It is a local prototype and is not suitable for network or multi-user deployment.

Click **Run complete synthetic story** to load the reproducible two-stream walkthrough. It displays a synthetic demographic record and dated labs, then seven days of activity/sleep/resting-heart-rate observations. Latest lab values and BMI map through explicit arbitrary formulas into dimensionless starting states; the sensor means alter illustrative ODE coefficients. The view compares a lab-only simulation with that fused run. A separate OLS forecast targets a **synthetic dimensionless TG proxy at 30 days**, evaluated on 100 separately generated held-out synthetic records against a persistence baseline. This demonstrates software behavior only: none of these mappings, target values, or performance metrics represents patient biology or clinical forecasting.

## Synthetic model and experiment

`py -3.15 src/train_synthetic.py --rows 8000 --seed 20261019` generates synthetic equation samples, splits them deterministically into 6,400 training and 1,600 holdout rows, fits OLS, compares prespecified ridge alpha 0.01, and writes the model JSON, residual plot, sensitivity summary, numerical refinement report, and a seeded propagation of assumed rate/initial-state ranges. No generated row is persisted. The propagated quantiles are assumption-driven, not calibrated uncertainty. CLI examples: `py -3.15 src/masld_twin.py --demo` and `py -3.15 src/masld_twin.py --input examples/synthetic_patient.json`.

The four ODE state variables (FFA, TG, ROS, ECM) are dimensionless arbitrary model units. Time is arbitrary, not a calendar duration. Literature motivates qualitative mechanisms only; it does not calibrate numeric values. Read [the model card](docs/MODEL_CARD.md), [state and parameter definitions](docs/PARAMETERS.md), [scientific assumptions registry](docs/SCIENTIFIC_ASSUMPTIONS.md), [machine-readable parameter registry](data/parameter_registry.json), [data dictionary](docs/DATA_DICTIONARY.md), and [generated experiment report](reports/experiment_report.md).

## 3D twin and visual meaning

The local CC0 liver and transparent body anatomy models are selectable, rotatable, zoomable, resettable, and synchronized to API-produced synthetic trajectories. Users can select zones, scrub or play time steps, switch generic assumptions, and compare baseline/scenario/difference outputs. The liver geometry stays fixed and does not morph to imply tissue change. If WebGL or a GLB file fails, a static liver illustration and the rest of the analysis remain available. See [asset licences and visual mapping](docs/MODEL_ASSETS.md).

Surface colors and zone hotspots map run-normalized TG, ROS, and ECM proxies. The scale is relative to that run's displayed baseline/scenario histories (or their absolute difference). It is a synthetic visualization convention and must not be read as pathology, disease progression, stage, severity, probability, or a measured quantity.

## Model scope and limitations

- Synthetic equation data only; no human or external training data, clinical endpoints, or external validation.
- No diagnosis, clinical risk, treatment effects, patient-specific forecast, or trained PINN. The demo includes only a synthetic 30-day target forecast and synthetic held-out benchmark.
- Arbitrary coefficients, state units, perturbation multipliers, and initial conditions; solver convergence does not establish biological validity.
- Report import reads supported text/CSV/JSON locally in the browser; it does not upload or persist a report. Scanned PDF/OCR is not supported.
- No authentication, persistence, MFA, database, or public deployment security. Keep the service loopback-only.
- No test establishes clinical validity or patient safety.

Further scope and planned scientific validation are in [docs/VALIDATION_PLAN.md](docs/VALIDATION_PLAN.md) and [docs/SECURITY_REVIEW.md](docs/SECURITY_REVIEW.md).
